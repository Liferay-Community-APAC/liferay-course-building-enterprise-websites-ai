Instructor guide

This guide is for the person running Building Enterprise Websites with Liferay and AI. Read it with the schedule, the instructor demo workbook and the day slides open.

What the course is, and isn't#

It's the Building Enterprise Websites with Liferay (BEWL) course in two days instead of three, rebuilt so that an AI coding agent does the building and the learner does the checking. The learning goal hasn't changed: learners leave knowing how Liferay builds enterprise websites (users and permissions, sites, pages, fragments, design, CMS, collections, commerce, APIs, workflow, search, objects, personalization). The agent is the tool that lets them cover all of it in two days, and the verify steps are where they learn the product: each one sends them to the screen where that capability lives.

Hold that line in class. When a learner says "the agent did it, it works", ask them to show you where in Liferay they checked it.

Before the course#

  • Two weeks before: send learners the prerequisites page. It covers Git, JDK 21, Blade, Docker with 8 GB of memory, the Liferay DXP and PostgreSQL Docker images, VS Code and their AI agent. They bring their own agent subscription.
  • One week before: remind learners to get their DXP activation key (the prerequisites page shows how): the free key from the Liferay DXP Free Tier, or a developer key issued to them on one.liferay.com. Each learner uses their own key; never put a key in the repository. Tell them the free key's one limitation: it has no Search Blueprints (Liferay Enterprise Search isn't in the Free Tier), so Levels 11.2 and 11.3 have free-key paths (Custom Filter widgets; expiration dates and a collection) and ⭐ 14.6 is skipped. Everything else is the same on both keys.
  • The day before: run the whole workbook on your own machine from a clean clone, with the agent you'll demo with (see Set up your own machine below). Note anything that changed with agent or DXP updates.
  • On the morning of day 1: share the repository URL (it's not on the prerequisites page) and walk the room through Setup S.0 (see The first 30 minutes below). The workbook is also published on the repository's GitHub Pages.

Set up your own machine#

Do this the week before, on the laptop you'll present from. You run the whole workbook once, in one copy of the course, and present from that finished build: the demo workbook assumes it. Live demos of a level's first prompt also run on it, because every prompt is safe to rerun.

  1. Install the prerequisites from the prerequisites page, and run its agent check prompt until every line passes. Use the agent you'll demo with; if you can, install a second one, so you can answer questions about both.
  2. Get a DXP activation key for yourself, the way learners do: the free key from the Liferay DXP Free Tier, or a developer key from one.liferay.com. Use a developer key for your demo build, so the blueprints of Level 11 are there to show; keep a free-key instance at hand if you want to walk free-key learners through their paths.

  3. Clone the course and open it in VS Code, exactly as learners do in Setup S.0:

    mkdir -p ~/courses && cd ~/courses
git clone https://github.com/Liferay-Community-APAC/liferay-course-building-enterprise-websites-ai.git bewl-ai

    Open ~/courses/bewl-ai in VS Code, trust the folder, open the terminal and your agent's chat.

  4. Run the whole workbook: Setup S.1 to S.5, then Levels 1 to 13, including the verify steps. It takes most of a day. Note the prompts where your agent needed help: learners' agents will too.

  5. Check the result with demo D1.1: Home as Guest and as Terrence. Then stop Liferay and PostgreSQL (docker compose stop at the workspace root): the data stays in Docker volumes for the course.
  6. Keep the build. Don't reset it before the course. Every copy of the course uses the Compose project clarity (containers clarity-postgres and clarity-liferay, and their volumes), so a second clone on the same laptop would share this database: keep one copy.
  7. Prepare the projector view: VS Code's zoom (View → Appearance → Zoom In) so the back row can read prompts, the terminal and the agent's chat side by side, and a browser with the workbook, the slides and a private window. Try the slides' ▶ Present button once: it puts the deck full screen and opens a presenter window (timer, current and next slides, speaker notes). Allow pop-ups for the slides' site, then move the presenter window to your laptop's screen and the full-screen deck to the projector.

The first 30 minutes#

Most setup problems show up in the first half hour. Before the first slide, put the repository URL on the screen; then, after the kickoff slides:

  1. Walk the room through S.0 together, step by step, on the projector. Don't let people run ahead: clone, open the folder in VS Code, trust it, open the terminal, open the agent's chat, send the S.0 prompt.

  2. Check every laptop before moving on. Each learner's agent should name dxp-2026.q3.10 and the bewl-ai folder. The usual problems:

    • VS Code opened a file instead of the folder, or the parent courses folder: reopen the right folder.
    • Restricted Mode: click Manage in the banner and trust the folder.
    • The clone is inside a OneDrive, iCloud Drive or Dropbox folder: move it to ~/courses or C:\courses.
    • Windows: Filename too long during the clone. Run git config --global core.longpaths true, delete the half-cloned folder and clone again.
    • The agent isn't signed in, or Copilot is in Ask mode instead of Agent.
    • Docker isn't running: with Colima, run colima start; with Rancher Desktop or Docker Desktop, open the app. Do it before S.2.
    • Two Dockers installed (Docker Desktop and Colima or Rancher Desktop): quit the one the learner doesn't use, and check docker context show.
    • Docker has less than 8 GB of memory: Setup S.2 step 2 has the setting for macOS and Windows. Check with docker info --format '{{.MemTotal}}' (about 8000000000 or more).

  3. Then demo S.1 (D1.4) and let learners run S.1 to S.5 at their own pace while you walk the room.

Running the hands-on blocks#

  • Demo the first prompt of each level on the projector, including the verify step. Then let learners run the rest. The instructor demo workbook has the step-by-step for every other demo, with optional prompts.
  • One agent session per exercise keeps costs and confusion down. If a learner's agent goes off track, have them start a new session: solution-context.md and solution-index.yaml carry the context.
  • Agents differ. Prompts are written to work with Claude Code, Codex and Copilot in agent mode. A weaker model may need the skill named explicitly (the exercise's Skills line) or a follow-up ("read the X skill and try again").
  • Learners never start or stop Liferay through the agent. If an agent offers to, they say no and do it themselves.
  • Verification is read-only. Encourage learners to open the editors to look, then leave without saving or publishing. The places where they act (approving a workflow task as Daniel in 12.4, and the few settings with no API) are marked 📋.

Catching up#

The levels are chained: a learner who can't finish Level 6 can't do Level 7. Three safety nets:

  1. Rerun the prompts. Every prompt is written to be idempotent (upsert by external reference code), so rerunning an earlier one is safe.

  2. A catch-up kit. Each one holds the solution up to a level: the site initializer (and, from Day 2, the theme), re-runnable scripts that create the data, and a README with a prompt for the learner's agent. Each was proven on an empty database with the reference tests below.

    Kit Leaves the learner ready for Use it Takes about
    catch-up/level-4-start/ Level 4 Day 1 at 14:20, for anyone still stuck in Level 3 5 minutes
    catch-up/day-2-start/ Level 7 Start of Day 2 10 minutes
    catch-up/level-10-start/ Level 10 Day 2, after lunch 15 minutes
    catch-up/level-12-start/ Level 12 Day 2, after the afternoon break 15 minutes

    Applying a kit replaces the learner's own work for the levels it covers, so offer it when they are more than one level behind, not to fix one exercise. Each README lists what the learner still does by hand: the 📋 steps of Levels 2.3 and 2.5 (virtual host, and the instance's home, landing and logout pages), which have no API. The kits come from a clean run on DXP 2026.Q3.10: re-prove them when you move the course to a new release.

  3. Check where a learner stands. The reference tests have one test per acceptance criterion. Run them against a learner's workspace up to their level (npx playwright test specs/level-6.spec.ts) to see exactly which criteria fail, or against your own demo build before the course.

The bonus level: Liferay AI Hub#

Level 14 is optional, for learners who finish early or want more after the course. It's the course's showcase for Liferay AI Hub: learners build an AI chatbot with AI Hub's setup (a Liferay Search agent, an LLM agent, a chatbot, then Liferay's own Click to Chat with the AI Hub provider), in a course mock of AI Hub that runs on their computer (bonus/ai-hub/, Node.js 20, no install). It answers from the site's content, searched as Guest, and the answers are written by the learner's own agent CLI (Claude Code, Codex, Copilot or Gemini), so no AI Hub access or API key is needed.

  • Try it on your machine first: about 45 minutes. Each answer takes 5 to 30 seconds and uses the learner's agent subscription. It was tested with Claude Code; tell learners on other agents it's a bonus, not a promise.
  • It needs a finished build up to Level 7 (content to answer from, and the master pages). A level-10-start or later catch-up kit is enough.
  • The one step that surprises learners is 14.2: the headless search API answers 403 to Guest until a Service Access Policy allows it. It's the course's "permissions fail silently" lesson again, at the API gate instead of the content gate.
  • It's prompt-based, like the other levels. The agent sets the mock up through its JSON API (documented in bonus/ai-hub/README.md) and the learner checks each step in the console's screens. Two steps stay by hand: starting the mock (learners start servers themselves), and the Service Access Policy in 14.2, which has no API, so the agent gives the UI steps.
  • Click to Chat is the real one. In 14.5 the agent writes two system-scoped OSGi config files (AI Hub: the mock's placeholder Client ID and Secret, Service URL http://localhost:3010; instance Click to Chat: enabled, Inherit or Override) and the site's Click to Chat in site-settings.json (AI Hub provider, account CLARITY_ASSISTANT, guests allowed). Liferay then loads the chat bubble from the mock, as it would from AI Hub; nothing calls Liferay's cloud. The release flag AI Hub (LPD-62272) isn't needed: it only shows the AI Hub screen in Instance Settings.
  • Sell the real thing: the level's intro explains why AI Hub (Agent Builder, Liferay's ready-made agents, grounding in Liferay content, guardrails and risk classification, Click to Chat and the CMS AI Assistant), and its end points learners to their Liferay account team. Mention it when you present the bonus slides, even to learners who won't do the level.
  • With the real AI Hub, the same build is the masterclass's Energy Advisor exercise: AI Hub's console, a Search Blueprint for the RAG config, and Click to Chat in Site Settings.

Course feedback#

Collect feedback before learners leave, on the last slide of Day 2. Set up a form in your organization's form tool (Microsoft Forms, Google Forms or your LMS) with the questions below, and share its link in the class chat or as a QR code on the closing slide. The first three are the ones that improve the next run of the course; keep them even if you drop the rest.

  1. Which level was hardest, and why? (Level 1 to 13, plus a comment)
  2. Where did your AI agent get stuck or go wrong? Which agent and model did you use? (comment)
  3. Did the ✅ Verify steps help you learn where each feature lives in Liferay? (1 = not at all, 5 = a lot, plus a comment)
  4. How was the pace? Day 1 and Day 2 each: too slow, about right, too fast.
  5. Did you finish the prerequisites before Day 1? (yes, partly, no) What got in the way?
  6. How likely are you to recommend this course to a colleague? (0 to 10)

After the course, read the answers to questions 1 and 2 against your own notes on where the class stalled: they show which prompts, skills or verify steps to fix first.

When something goes wrong#

Symptom Likely cause Fix
docker compose up downloads the images again, slowly The images weren't pulled before the course Let it download, or load them from a USB stick (docker save on your laptop, docker load on theirs).
clarity-liferay restarts in a loop, or exits with code 137 Docker doesn't have enough memory Raise it to 8 GB or more (Setup S.2 step 2), then docker compose up -d.
Linux: the agent can't read bundles/logs The learner's user ID isn't 1000 (id -u) Use the Tomcat bundle (Setup S.2, optional section).
Liferay won't start: database connection refused PostgreSQL isn't running docker compose up -d, wait for healthy. With the Tomcat bundle, start Liferay again.
Port 8080 or 5432 in use Another Liferay or PostgreSQL, or a Tomcat bundle and the container both started Stop the other one, or change the port in docker-compose.yml and portal-ext.properties (and server.xml for the Tomcat bundle).
The agent's MCP server shows connected with no tools Liferay restarted since the session started Reconnect or restart the agent session.
/o/mcp answers 404 The MCP Server instance setting is off Rerun prompt S.4.
A deploy "succeeds" but nothing changes Unchanged zip, or the wrong deploy order Ask the agent to blade gw clean deploy and check the Initialized log line, per the site-initializer rules.
A page shows content for the admin, not for Guest Permissions, or the Space isn't connected to the site Ask the agent to check Guest access (rules/guest-access.md) and the Space's connected sites.
The first sign-in shows a Terms of Use notice Liferay Enterprise Search notice on first admin sign-in Read and close it with Done. Until then it covers the admin screens, and the reference tests that read them fail.

Resetting a learner's environment#

To start over completely, at the workspace root:

docker compose down -v

That deletes the database and Liferay's data. Then delete the bundles folder (in VS Code's Explorer, or rm -rf bundles on macOS and Linux), start again with docker compose up -d (Setup S.2), and rerun the prompts, or use the catch-up starting point. With the Tomcat bundle, stop it first (blade server stop), and run blade server init after deleting bundles.
