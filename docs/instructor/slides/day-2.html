Displaying content

Map content, don't copy it

  • A page shouldn't hold copies of content: it maps to it
  • A fragment's editable image, text or link maps to a content field
  • Change the content and every page that maps it updates
  • Map by a reference that survives a rebuild, not a numeric ID

Structure is the what and mapping is the how: keeping content and display separate lets one item render in several places. In 7.1 the Home images come from the Marketing Space's files instead of copies on the page. Demo selecting the banner's Image fragment in edit mode, where Source Selection reads Mapping. Learners ask why the prompt prefers an external reference code; numeric IDs change when the site is rebuilt on another environment.

Displaying content

Display page templates

  • Each item gets its own page at its own URL
  • Built once per structure, fields mapped onto fragments, no code
  • Content, object entries, products, categories and more
  • Clarity: Article and Leadership Profile, each marked default

A structure can have several display page templates for different scenarios, each with its own URL; the default is used when none is named. The Article template uses the Primary Master Page and the Leadership Profile one uses the Secondary. Demo opening one article's display page URL in a private window. If a display page answers 404 for Guest, the Space's content may not be viewable by Guest or the Space isn't connected to the site: ask the agent to check both.

Displaying content

Manual or dynamic collections

Manual

  • You hand-pick the items and their order
  • Clarity: Helpful Articles on Home and FAQ

Dynamic

  • Rules select the items, such as a category
  • Clarity: one FAQ collection per category, and Announcements

A collection only selects. A Collection Display renders it, item by item, with any fragment. One collection can feed several displays, and Asset Publishers still fit complex templates.

Collections separate selection from display, so one collection renders in several ways: Helpful Articles appears as Clarity Cards on both Home and FAQ. Use collections for selection even when you still need an Asset Publisher for complex FreeMarker templating. Collection providers are also created when a structure is published, and on day 2 afternoon a search blueprint becomes one. Learners ask why the FAQ needs four collections; each FAQ section filters on its own category.

AI in Liferay DXP

Auto-tagging and AI Hub

  • Auto-tagging suggests tags as content is created or changed
  • AI Hub is a separate product that connects to DXP
  • Its agents are built in an Agent Builder; their logic is a Liferay workflow
  • Liferay's own agents are read-only: duplicate one, then change the copy
  • An AI Assistant in Liferay CMS routes each request to the right agent

The original bonus enabled auto-tagging for web content with OpenNLP; demo the auto-tagging configuration if you have time. AI Hub runs in its own SaaS environment, bought through Marketplace, and it must reach your environment from the internet because it calls back into it. Data sources let agents answer from crawled websites, and instructions add tone and policy. Learners ask whether AI Hub needs a separate license; yes, it's its own product.

Commerce

Catalogs, products and channels

  • A catalog holds what exists, with a default language and currency
  • Product types: simple, grouped, virtual and diagram
  • Specifications describe products, grouped in specification groups
  • A channel is where products are sold, linked to a site or used through APIs

Clarity's products are content held in Liferay Commerce, so nothing has to be rebuilt elsewhere. Creating a catalog also creates its base price list and promotion list. Specifications marked for faceted navigation become filters on the Product List page in 8.5. Learners ask why a B2B channel for a site that doesn't sell; Clarity's site showcases products and sends visitors to Contact Us, and the site type is from the brief.

Commerce

Product pages or a product display page template

Product page

  • A content or widget page built from product widgets
  • Widgets support widget templates
  • Required on older versions

Product display page template

  • Built with standard Page Builder features
  • Fragments map to product fields
  • The modern choice; a few features may lack a fragment

Listing pages (PLP) list a category's products; detail pages (PDP) show one product. Both matter for SEO.

Clarity uses both ideas: a Product List page that displays a category with search widgets and a widget template, and a Product Details display page template for each product. A product listing page is really a search page with filters applied up front, which links to this afternoon's search block. Demo the Products page's category cards and its widget template. Learners ask why use a widget template at all; the Commerce Categories Navigation widget needs one for the bento layout.

Headless APIs

Everything your agent did went through these

  • REST and GraphQL for sites, pages, content, users, commerce and more
  • Documented with OpenAPI; run them at /o/api, the API Explorer
  • Remote apps use OAuth 2.0, with scopes for least privilege
  • Guest access is off by default; opening it is a deliberate policy
  • The MCP server exposes these same APIs to your agent

Headless keeps systems decoupled: build a UI in any framework, deliver to web and mobile from one source, migrate from legacy systems. Basic authentication suits testing but not production and isn't available on SaaS; OAuth 2.0 registers each app with scopes. Demo the API Explorer: choose headless-admin-user, find GET my-user-account and execute it, the same call the agent made in Setup. Learners ask about building their own endpoints; API Builder does it in the Control Panel without code, while REST Builder is a developer toolchain not available on SaaS.

Headless APIs

Batch imports of legacy data

  • Batch endpoints take a whole JSON array in one request
  • Liferay processes it as an asynchronous import task
  • Poll the task until it completes, then check the counts
  • Clarity: a blog post, three articles, eight products, twelve locations

Clarity has content and data in its old portal and its product information system; this level brings it across securely. The prompts ask the agent to show the batch request it sends and to report the task status and processed count. Demo running GET on the import task in the API Explorer: executeStatus reads COMPLETED. Learners ask why not post items one by one; for hundreds of items a batch is one call and one task to check.

Workflow and publishing

Workflow is how content gets published

  • Draft: saved by the author, not on the site
  • Pending: submitted, waiting for a reviewer, still not on the site
  • Approved: published, live for visitors
  • Rejected: back to the author to update and resubmit
  • Nothing reaches visitors before approval
  • Scheduling extends it: a future display date publishes later

Workflow puts a review step between submitted and published; Clarity uses Single Approver with the Content Manager role as reviewer. Walk the states: only Approved is visible to visitors, and a rejected item goes back to its author. Scheduling is an extension, not a separate tool: approve today, and the entry goes live on its display date. Existing customers may use Publications to release batches of page changes; it's in maintenance mode on 2026.Q1 with no replacement, so this course publishes through workflow. Learners ask how to release several changes at once; schedule them with the same display date.

Workflow and publishing

Publishing a site-wide change

  • The announcement bar shows the newest Announcement entry of the Marketing Space
  • Put Announcement under the same workflow, and every page is gated at once
  • Christian submits "Spring Campaign": the bar doesn't change
  • Clara approves it: the bar changes on every page
  • The agent can act as a persona by signing in with their credentials

One Announcement entry feeds the bar on every page that uses the Primary Master Page, so a single approval is a site-wide release. Acting as a persona lets the agent test the workflow end to end: Liferay applies that user's permissions and records them as author or reviewer. This is the course's answer to what Publications used to do for a campaign: prepare it, review it, release it in one step. Learners ask why the bar still shows the old text after approval; the page may be cached for Guest, so wait a minute and reload.

Search

Search in Liferay

  • One search API over Elasticsearch or OpenSearch
  • A wide range of content types indexed out of the box
  • A search page is widgets you assemble: bar, results, facets, options
  • All search widgets on a page share one search
  • Synonyms and result rankings tune results for little effort

Clarity wants marketing to design the search experience, customers to find documentation, and results personalized by role. Each search capability is a component, so you build the page the business needs. Demo the site's Search page with the global search bar and a facet. Learners ask whether CMS content is searchable from the site; yes, once its Space is connected to the site, which is why the HR Space connection matters in 11.1.

Search

Facets and the Open Positions job search

  • More than ten facets ship: categories, tags, dates, content type
  • Several facets are specific to commerce
  • Custom facets work with almost any indexed field
  • Templates give a facet a custom view
  • Clarity: a category facet grouped by Region, Location and Job Positions

In 11.1 the agent builds Open Positions with a search bar, a category facet grouped by vocabulary, results, and Search Options allowing empty searches. If the default facet display can't group, the agent writes a facet widget template. Demo searching Developer as Guest and narrowing by the Remote location. Learners ask why empty searches matter; without them the page shows nothing until a visitor types.

Search

Search Blueprints

  • Change how results are filtered and scored, with no code
  • A blueprint is a set of query elements: filters, boosts and more
  • A page applies it through the Blueprints Options widget
  • A blueprint can be a collection provider for a Collection Display
  • Results can differ by user, page or audience

Clarity uses two blueprints: one that keeps only job listings and boosts Associate positions, and one that lists future hiring events (Event Information entries in the Events Space) as a collection on the Events page. The agent validates each blueprint with its preview endpoint before saving. Demo the Blueprints application and its Preview with the search Associate. Learners ask how this relates to semantic search; semantic search interprets meaning through text embeddings, and blueprints shape the query either way.

Objects

Extend in the right order

  1. 1Out of the box: check what Liferay does today
  2. 2Low-code: Objects and workflow
  3. 3Client extensions: outside Liferay, upgrade-safe
  4. 4OSGi plugins: last resort, not on SaaS

Stop at the first option that solves the problem.

Liferay is built to be adapted without being altered, so what you extend today still upgrades tomorrow. Clarity's Contact Us form is a low-code case: an object, a form, a workflow and a data set, with no deployment for the object itself. Learners ask where client extensions fit in this course; the site initializer and Theme CSS are client extensions, step three. The Liferay Application Developer learning path covers the development side properly.

Objects

Liferay Objects

  • Define the data; Liferay generates storage, APIs and admin screens
  • Fields, validations, relationships and picklists
  • Permissions, workflow and search apply as everywhere else
  • Definitions move between environments with the site

An object is a first-class citizen of the platform: permissions and roles, workflow, indexing, and the audit framework all apply automatically. A picklist holds reusable, translatable options, like the Inquiry Types in English and Spanish. Demo Control Panel, Objects, Contact Us after 12.1: published, site scope, seven fields. Learners ask why Guest gets add but not view; visitors submit, they never read other people's submissions.

Personalization

Segments and experiences

Supported path: Data Platform

  • Liferay Data Platform is the source of truth for segments
  • Segments can use behavior, not only attributes
  • Needs an LDP workspace connected to each instance

In this course

  • DXP's own segments and experiences are deprecated on 2026.Q1
  • A Clarity Audience Container fragment checks the user's user groups
  • Decided on the server, so hidden content never reaches the browser

With Data Platform, an experience is a version of a page shown to a segment. A user-group check covers signed-in users only; anonymous and behavioral personalization needs Data Platform segments.

Tie this back to the Data Platform slide on day 1: in a real project you'd build the Distributors segment in Data Platform and target it with an experience of Home. DXP's own segments and experiences are deprecated on 2026.Q1 in favor of Data Platform segmentation, which needs a workspace connected to each instance, so the class has no exercise on it. Instead learners build a fragment that renders its drop zone only for a chosen user group, or only for everyone else. Learners ask when to use which; the container for signed-in users by user group, Data Platform segments for anonymous visitors, behavior, location or campaigns.

Performance tuning and maintenance

Tune from data, not defaults

  • Review settings for production: enable only the servlet filters you need
  • Use Liferay's cache levels deliberately
  • Adaptive Media resizes images for each device
  • Tune JVM heap and thread pools from monitoring numbers
  • Use the deployment checklist before go-live

Talk only, as in the original course. A copied setting is only a guess about how your site behaves; tuning brings many small gains, not one big one. Adaptive Media is free performance: smaller images on slow networks and better search ranking. A common question is what to tune on SaaS; Liferay runs the infrastructure there, so focus on content, images and page design.

Performance tuning and maintenance

Test, audit, monitor, upgrade

  • Performance testing: goals, a production-like environment, edge cases, analysis, repeat
  • Page auditing finds performance, SEO and accessibility issues
  • Glowroot and APM tools show where time goes; audit records show who did what
  • Treat an upgrade as a project: plan, test in lower environments, promote
  • With Support: be proactive, explicit and timely

Performance testing is ongoing: build it into the development lifecycle and retest after code or infrastructure changes. Demo Page Audit on Clarity's Home page if it's configured, and mention APM options such as Glowroot, Elastic APM, Dynatrace on PaaS, AppDynamics, Datadog and New Relic. Avoid upgrading in the middle of an implementation; on SaaS, Liferay applies the upgrade and you test it. Learners ask how the site in code helps upgrades; it can be rebuilt and tested on a lower environment.
